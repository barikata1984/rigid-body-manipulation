# 合成データセットの作成と OLS 同定結果の記録

作成・更新日: 2026-08-26。本文書は実行条件と測定結果の記録であり、評価手順の誤りと
データから確認できる事実を明記する。後続の担当者が独立に再計算できるよう、座標系、
入力系列、数値を省略しない。

## 1. 合成データセットを作った目的

1 回のシミュレーション実行から得るデータセットには、下流の 2 用途が同居している。

- 画像とカメラ姿勢: NeRF 系の物体再構成に使う。物体を全方位から均等に見る視点が必要。
- 動力学量 (物体姿勢、速度、加速度、レンチ、回帰行列): 慣性パラメータ同定と NeMD 学習に使う。
  慣性パラメータを励起する振動が必要。

従来の `excited` 軌道は「スプラインのベース軌道 + フーリエ励振」を波形レベルで加算していた。
この合成軌道では励振成分が視点の軌跡を乱し、物体を全方位から均等に見る条件が崩れる。
これが NeRF 側に不利に働く。

そこで軌道を 2 本に分離し、実行も別々に行い、データセットの段階で 1 つに束ねる方針に変更した。

- 画像・カメラ姿勢: 励振を含まないスプライン軌道の実行から取る。
- 動力学量: ベース軌道を持たない純励起軌道の実行から取る。

## 2. 合成の方式

### 2.1 下流ローダの制約 (調査結果)

`~/workspace/pixi-wisp-container/wisp/datasets/formats/nemd_standard_dataset.py` を読んで確認した事実。

- ローダは `transforms.json` の `frames` 配列を 1 行ずつ処理し、1 行から画像と動力学量の
  両方を取り出す。行数を先頭次元にしたテンソルに積み上げ、学習時は同じ添字で両方を引く。
  したがって「画像だけの行」「動力学だけの行」は表現できない。
- 色の損失は画像と描画結果のみ、動力学の損失は質量分布モデルとその行の速度・加速度・姿勢・
  レンチのみを使う。同一行の画像と動力学量は互いを参照しない。
- ローダは fps を読まない。フレームごとの時刻の項目も存在しない。
- カメラ内部パラメータは最上位から 1 組だけ読まれ、全フレームで共有される。
- 回帰行列はローダでは使用されない (本リポジトリ側の同定処理のために引き継ぐ)。

### 2.2 実装

`recorders/merge.py` (新規、コマンド名 `merge-datasets`)。

```sh
pixi run -e dev merge-datasets --spline-dir <画像側 run> --excited-dir <動力学側 run> --out-dir <出力>
```

処理内容:

- 両実行のカメラ内部パラメータと AABB スケールを照合し、不一致なら中断する
  (`--force` 指定時のみスプライン側の値で続行)。
- 行数を揃える。短い方は全フレームを使い、長い方はその全区間から等間隔に抽出する。
  抽出添字は i 番目を `round(i * (N-1) / (n-1))` とし、先頭は 0、末尾は N-1 になる。
- 各行はスプライン側の項目を土台にし、動力学に属する項目のみ励起側の対応行で上書きする。
  上書き対象: `pose_sen_obj`, `twist_sen`, `dtwist_sen`, `linacc_sen_obji`, `wrench` (`ft_sen`),
  `regressor`, `jointvars`。
- 画像とマスクはスプライン側から通し番号を振り直して配置する (ハードリンク、失敗時はコピー)。
- 出所の記録: 各フレームに `image_source` / `dynamics_source`、最上位に `merge_sources`
  (両側の run ディレクトリ、元フレーム数、採用添字列 `source_indices`、間引き方式 `subsampling`)。

補助コマンド `export-dynamics-csv` (`recorders/export_dynamics_csv.py`) で、
マージ結果の動力学量を CSV に書き出せる。

### 2.3 ノイズ系列の扱い

`main.py` と recorder は `primary_prefix` に応じて一方の系列を素の `.json`、他方を `.json.bak` として保存する。
今回のマージ前処理では、動力学側のノイズ入り系列を素の名前に手動で入れ替えてからマージした。
そのため、マージ済み出力の `transforms.json` はノイズ入り系列である。

## 4. OLS による同定結果

### 4.1 座標系と計算方法

各フレームの回帰行列 (6×10) とレンチ (6) を積み上げて `A` (行数 = フレーム数 × 6、列数 10)、
`b` (長さ = 行数) を作り、`numpy.linalg.lstsq(A, b)` で生の解 `x_sen` を求めた。
`regressor` と `wrench` はセンサ座標系、最上位の `global_gt` は物体 AABB 座標系である。
したがって、比較に使う推定値は

```python
import numpy as np
from liegroups import SE3
from dynamics import transfer_iparams

x_sen = np.linalg.lstsq(A, b, rcond=None)[0]
pose_obj_sen = SE3.from_matrix(np.asarray(frames[0]["pose_sen_obj"], dtype=float), normalize=True).inv()
x_obj = transfer_iparams(pose_obj_sen, x_sen)
err = x_obj - np.asarray(t["global_gt"], dtype=float)
```

として得た `x_obj` とする。これは commit `7d6f863` 以降の `main.py` の比較・保存方法と同じである。
`pose_sen_obj` は z 軸 180 度回転 (`diag(-1,-1,1)`) なので、今回の平行移動なしの姿勢では
`mx`、`my`、`iyz`、`izx` の符号が反転する。

表中の誤差率は `100 * abs(err) / abs(GT)`。`abs(GT) < 1e-8` の GT≈0 成分は割合を算出不可として
`— (GT≈0)` とした。相対残差は全て `‖A @ x_sen − b‖ / ‖b‖` であり、センサ系の方程式適合度である。
これは物体 AABB 系での GT 精度を表さない。

### 4.4 座標変換漏れとノイズに関する事実

- 初版では、センサ系の生の `x_sen` を物体 AABB 系の `global_gt` と直接比較していた。
  z 軸 180 度回転のため、loaded_dice の clean 系列で `mx`、`my`、`iyz`、`izx` の符号が反転して
  見える問題は、この評価手順の座標変換漏れであった。変換後の clean 推定値は GT と同じ符号であり、
  これは未解決のデータ異常ではない。
- hammer のノイズ問題は残る。600 フレームでは noisy L2 が 0.0858834599274、clean L2 が
  0.000337139221098 で、noisy 推定は主に `mz`、`ixx`、`iyy` で真値より小さくなる。
  これらは A 側の観測ノイズによる減衰バイアスと整合する。hammer の座標変換で符号が変わる 4 成分は
  GT≈0 なので、変換の有無は L2 をほとんど変えない。
- loaded_dice は変換後、noisy L2 が 0.00189493293304、clean L2 が 2.45767809597e−05 である。
  clean の真値が 1e−8 以上の成分の絶対相対誤差は最大 0.676953%。
- clean の低い相対残差（hammer 7.23274334845e−05、loaded_dice 8.56549588212e−05）は、
  センサ系連立方程式への適合度を示す。GT 精度を直接示す値ではない。
