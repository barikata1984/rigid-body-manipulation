# Tracking Performance Improvement & LQR Gain Tuning Roadmap (2025-08-14)

## 1. 現状課題 (Summary)

- q3 (下段オレンジ) 軸で後半に大きな振幅増大とバイアス状のドリフト。
- 他軸も位相遅れと振幅ミスマッチ (実績が目標より遅れ/縮小/過大) が散見。
- 目標(破線)と実績(実線)の重なりは限定的で「高精度追従」とは評価しにくい。
- Q = I, R = diag([100,100,100,10000,10000,10000]) と極端に非均一な入力ペナルティ設定。

## 2. 主要な症状と仮説

| 症状 | 可能原因 (仮説) |
|------|----------------|
| 位相遅れ | R 過大で入力抑制 / Q_pos が低く応答性不足 / 速度推定遅れ |
| 振幅不足 or 途中から膨張 | 不適切な R バランス / モデル摩擦未補償 / 線形化点ずれ |
| q3 のドリフト | 入力不足 (R 大) + 摩擦/重力不整合 + 積分成分なし |
| ピーク付近の誤差 | 高周波成分が閉ループ帯域を超過 / 逆動力学 FF 無し |
| 軸間バラツキ | 各軸の物理スケール差を Q に反映していない |

## 3. 優先度付き対策一覧 (High → Low)

1. LQR の R 再スケーリング & Q の分解 (pos/vel 重み導入)  
   *Why:* 応答性と減衰のコア。現状 R の極端差が回転側の制御トルクを抑制し位相遅れ/振幅誤差を誘発。Q=I では軸特性を反映できない。
2. 逆動力学フィードフォワード (feed-forward torque) 追加  
   *Why:* LQR を真の残差補償に集中させ位相遅れ・定常偏差を減少。必要トルクの基礎を先渡しすることで R を過度に下げずに追従性向上。
3. 軌道帯域の適合 (高周波成分の平滑化 / 振幅再調整)  
   *Why:* 制御帯域を越える周波数を含む目標は不可避に位相遅れと振幅劣化を起こす。実行可能範囲へスペクトル調整。
4. Bryson's rule に基づく初期正規化 (状態/入力の最大許容値でスケーリング)  
   *Why:* 各軸同一基準で Q,R を初期化し調整ステップを体系化。チューニングの属人性低減。
5. 速度・加速度推定改善 (数値微分ノイズ低減: Savitzky–Golay 等)  
   *Why:* ノイズ/位相遅れを減らし Q_vel 強調時の不安定化を防ぐ。
6. 摩擦・減衰パラメータ推定/補償  
   *Why:* 定常誤差・ドリフト (特に低速域) を減らせる → R を上げても追従性維持。
7. 積分状態 (LQI) / 状態拡張  
   *Why:* 重力・摩擦モデリング誤差によるバイアスを除去。大きな I 追加前に 1–6 を実施して残差が小さくなってから。
8. 自動ゲイン探索ツール (グリッド/ランダム + 指標ログ)  
   *Why:* 手作業試行回数削減。客観指標(J=RMSE+α|u|∞+βSettling)最小化。
9. 入力飽和監視とアンチワインドアップ  
   *Why:* 飽和が隠れ原因ならゲイン調整だけでは改善しない。制限見える化。
10. モデル同定ループ (TLS/LS → A,B 再計算 → 再LQR)  
   *Why:* 線形モデル適合度向上でゲイン再設計を安定化。ただし上位施策後。

## 4. 対策 1 (最重要) 詳細手順

### 4.1 目標構造

- 状態順序仮定: [q(0..nv-1), qdot(0..nv-1), (actuator states...)]
- Q = diag([w_q_i, w_qdot_i, w_act_j]) を採用。
- R = diag(r_i)。

pos_weights = [80,80,80,120,100,100]
vel_weights = [8,8,8,12,10,10]
input_gain  = [150,150,150,3000,3000,3000]
### 4.2 初期値案

```text
pos_weights = [80,80,80,120,100,100]
vel_weights = [8,8,8,12,10,10]
input_gain  = [150,150,150,3000,3000,3000]
```

(元の [100,100,100,10000,10000,10000] より回転側緩和)

### 4.3 実装ステップ

1. `LinearQuadraticRegulatorConfig` に `pos_weights`, `vel_weights` を追加。
2. `update_control_gain` で `nv = m.nv` を基に Q を組成。
3. YAML (`base.yaml`) に新しいリストを追加し、未設定時はデフォルト (一律値) を使用。
4. シミュレーション実行 → 画像保存 → 目視。
5. 改善指標: 位相遅れ減少 / 振幅整合 / ドリフト縮小。
6. まだ遅い軸: その軸の R を 10–20% 低減 or pos_weight 増加 (≦+25%)。
7. オーバーシュート過大: 対応軸 vel_weight ↑ (倍まで) or R 少し ↑。

### 4.4 将来拡張

- YAML フラグ `use_integral: true` で LQI 拡張。積分状態を末尾に追加し Q_int 小さめ (1–5)。
- 自動探索スクリプト `tune_lqr.py` を追加し候補セットをバッチ実行。

## 5. 対策 2: 逆動力学フィードフォワード

- 目標軌道 (q, qdot, qddot) から逆動力学トルク `u_ff` を算出。
- 制御入力: `u = u_ff - K * e_state`。基底トルク供給で K 実効値を抑制しつつ高速応答。
- MuJoCo の mj_inverse / 自前逆動力学関数活用。

## 6. 対策 3: 軌道帯域適合

- 目標軌道を FFT → 振幅スペクトル確認 → 閉ループ推定帯域 (Bode 曲線 or シミュレーション応答) 超の高周波成分除去 (低通フィルタ or smoothing spline)。
- 位相遅れ/振幅歪みが減り LQR 調整自由度増。

## 7. 対策 4: Bryson's Rule

- 最大許容値: |q_i|max, |qdot_i|max, |u_i|max を仮設定。
- Q_ii = 1 / (|x_i|max)^2, R_jj = 1 / (|u_j|max)^2 で初期化。
- その後スケーリング係数 α_Q, α_R を 10^[-1..1] 範囲で微調整。

## 8. 対策 5: 速度推定改善

- Savitzky–Golay (window ~ 2–3 * (1/f_ctrl), poly 3) で q → qdot, qddot 推定。
- ノイズ低減で過大ゲイン時の振動リスク軽減。

## 9. 対策 6: 摩擦/減衰補償

- 残差トルク vs 速度を散布図化 → 静摩擦 + 粘性摩擦近似 (τ ≈ τ_c sign(ω) + b ω)。
- 推定後補償トルクを ff に加算し定常偏差縮小。

## 10. 対策 7: LQI (積分状態)

- 状態拡張: x_e = [q_err, qdot_err, ∫q_err].
- 拡張 A,B を構築し Q に ∫q_err の重みを小さめに付与。オフセット除去。

## 11. 対策 8: 自動ゲイン探索

- 候補セット (α_Q, α_R, 比率 pos:vel) をグリッド / ランダム。
- 指標: RMSE_pos + λ*settling_time + μ*|u|∞。
- 最良組をログ JSON 化。

## 12. 対策 9: 入力飽和監視

- 制御ループで |u| 比率 vs 物理最大値を記録。
- 飽和率 > 5% のステップ多数 → 軌道/ゲイン再検討。

## 13. 対策 10: モデル同定ループ

- 既存 TLS で慣性推定 → 更新後再線形化 (A,B)。
- 新 (A,B) で再LQR → 収束まで 3–5 iteration 目安。

## 14. 推奨最初の 2 サイクル (Practical Quickstart)

Cycle 1:

1. 対策1 を導入 (Q 分解, R 緩和)。
2. シミュレーション → 画像比較。
3. 軸ごとに R or pos_weight 微調整 (一回 ±10〜20%)。

Cycle 2:

1. 逆動力学フィードフォワード追加 (対策2)。
2. 必要なら軌道平滑化 (対策3)。
3. まだドリフト残存なら摩擦補償 or LQI 導入検討。
