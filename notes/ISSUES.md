## [2026-07-08] q4(pitch) の特異点回避が構造的に機能しない

2026-07-02 に発見した「singularity_margin が coeff_bounds に対して有効に機能していない」問題を追跡した結果, より根本的な設計矛盾が判明した.

`main_trajectory` の `start_pos[4]=end_pos[4]=0` により, q4 のベース軌道は常に 0 (定数). q4 の動きは励起成分 (フーリエ級数 × 窓関数) のみに由来するが, 窓関数の境界条件により励起は t=0, t=duration で必ずゼロになる. したがって **q4 は軌道の始点・終点で必ず q4=0 (特異点そのもの) になる**. これは `singularity_margin` をどんな値に設定しても (0.15 でも 0.1 でも), 始点・終点では必ず違反する構造的な矛盾であり, margin の調整では解消しない.

git 履歴 (`bf017ea`, 2026-07-01, Co-Authored-By: Claude) を確認したところ, `start_pos[4]=end_pos[4]=0` は特異点回避機能の実装と同じコミットで設定されており, 実装当初から意図と設定が食い違っていた可能性が高い.

実際にシミュレーション (`main.py`, hammer object) で検証したところ, q4 が特異点近傍で振動し続けても LQR 追従は発散しなかった (追従誤差最大 0.00093 rad). ただしこれは q4 の励起振幅自体が小さい (実機速度・加速度制約に対し使用率15-30%程度, `compute_fourier_bounds` の保守性による) ため「動きが小さく追従が簡単なだけ」であり, 特異点近傍での頑健性を証明するものではない.

対応候補(未決定): `main_trajectory` の q4 の `start_pos`/`end_pos` を特異点(0)から十分離れた値(例: 0.3 rad 程度)に変更する. これはタスク定義(ロボットに何をさせるか)自体の変更を伴う.
