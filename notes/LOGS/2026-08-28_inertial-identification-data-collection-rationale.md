# 2026-08-28 慣性同定用データ収集方式の根拠整理

## Topic
MuJoCo 時刻同期、実測ノイズ、D-opt 励起軌道採択までの履歴

## Summary
MuJoCo の旧記録ループには、積分後の状態と積分前の派生量を同じ frame に保存する 2 ms の時刻ずれがあった。
このため旧ループの OLS 数値を採否根拠から外した。
実機ログと仕様に基づく `empirical` noise profile は、同期修正後の評価へ引き継いだ。
同一条件のフル比較では、慣性パラメータ全体の情報量と主評価成分の共分散指標を根拠に D-opt を採用した。
D-opt 内の実行用候補は、目的値だけの最良 seed43 ではなく、質量・一次モーメント・慣性対角との均衡がよい seed44 とした。

## History

### MuJoCo API の呼び方による 2 ms 時刻ずれ

高励起の D-opt 8π 軌道では、クリーン条件でも `regressor @ GT` と wrench の残差が増えた。
当初は次の原因候補を比較した。

- 座標変換の誤り
- 剛体回帰式の誤り
- 高速回転時の MuJoCo 計算の破綻
- 状態と力覚値の記録時刻の不一致

同時刻の状態を明示的に与える診断では、回帰式と wrench が機械精度で一致した。
この結果から、問題は物理式ではなく記録時刻に絞られた。

旧ループは `mj_step` 後の `qpos/qvel` を保存していた。
同じ frame の `qacc/sensordata` は、`mj_step` 内の積分前 forward dynamics で計算された値だった。
MuJoCo の timestep は 0.002 秒である。
したがって、1 frame の中で状態だけが 2 ms 新しくなっていた。
この API 契約と診断値は [2026-08-26 の同期修正ログ](2026-08-26_mujoco-time-sync-fix.md) に記録されている。

修正案として次の三つを比較した。

- 各 physics step 後に `mj_forward` を実行する
- 積分前 state を退避して記録する
- 記録 frame の直前だけ `mj_forward` を実行する

毎 step の forward は約 91% の負荷増だった。
記録時だけの forward は約 15% の負荷増だった。
記録時だけの案は、画像、姿勢、記録時刻の規約を変えなかった。
同じ案は integrator にも依存しなかった。
以上から commit `44bde35` で記録 frame 直前の `mj_forward` を採用した。
loaded_dice の回帰試験では、修正後の `regressor @ GT` と wrench が `rtol=1e-13`, `atol=1e-14` で一致した。

この修正により、旧ループで作成した LS、TLS、OLS の数値は励起方式の採否根拠から外れた。
画像、マスク、カメラ軌道、GT、ノイズ過程の単体統計は、この時刻ずれだけでは無効にならない。

### ノイズレベルの調査と現行 profile

旧既定値には、力が 2 N、トルクが 0.1 N m という placeholder が残っていた。
FT300-S の公称 signal noise は、力が 0.1 N、トルクが `[0.005, 0.005, 0.003]` N m である。
旧値は力で公称値の 20 倍だった。
トルクでは軸により公称値の 20 倍から約 33 倍だった。
loaded_dice ではトルク信号よりノイズが大きくなり、物理的に不適切な負の主慣性を生じた。
この既定値は commit `d8f9eb7` で修正した。

関節側も、並進 `5.0e-4 m`、回転 `1.0e-3 rad` という旧値が実機より大きかった。
commit `df76d91` では仕様値を根拠に、並進 `2.0e-5 m`、回転 `1.0e-4 rad` へ下げた。
同じ変更で乱数 seed を設定・記録できるようにした。
この段階の値は工学的な仕様値であり、後続の実機ログによる校正値ではない。

実機記録 `replay_recording_2026-08-04_09-14-56/` を用いた調査では、回転関節の短期位置変動を `0.983e-5` から `1.76e-5 rad` と見積もった。
現行の回転 3 軸は `1.5e-5 rad` である。
速度は同じ位置系列から 34 ms の因果差分で求める。
加速度はその後退差分へゲイン 10 の一次 low-pass filter を適用する。
独立な位置・速度・加速度ノイズを足す旧方式は `legacy` profile に限定した。

現行 `empirical` profile の力覚標準偏差は、力が `[0.0668, 0.0831, 0.0654]` N、トルクが `[0.00338, 0.00302, 0.000989]` N m である。
同 profile は実測した軸間相関、lag-1 自己相関、力 0.01 N・トルク 0.001 N m の量子化も持つ。
この実装は commit `16ae308` に入った。
詳細な導出と同期後の因果評価は [データセット・ノイズモデルのログ](2026-08-26_dataset-merge-and-noise-model.md) に記録されている。

最初の 3 並進軸を直接計測した実機ログはない。
現行作業ツリーの `1.0e-5 m` は、UR5e の手先観測等価値 `[7.289e-6, 5.131e-6, 8.398e-6] m` を保守的に丸めた値である。
これは物理的な直動アクチュエータの校正値ではない。
同期修正後の既存比較は変更前の `2.0e-5 m` 条件であり、現行値による最終データセット評価とは区別する必要がある。

### D-opt 採択までの比較

初期実装は情報行列の条件数を最小化していた。
commit `66dc37b` で `-log det(F^T F)` を最小化する D-opt と multistart が追加された。
commit `1496827` では、パラメータ単位への依存を除くため列等化後の条件数が導入された。
列等化後の条件数は列間相関を測るが、各列の絶対振幅と信号対雑音比は測らない。
同期後評価でも、列等化後の条件数が小さいだけでは慣性列が十分に励起されないことを確認した。

既存の nomain 軌道と D-opt 8π 軌道は、目的関数、base trajectory、制約、最適化予算が同時に異なっていた。
その比較は候補発見には使えたが、D-opt の因果効果には使えなかった。
2026-07-15 の比較も、8π base drift の構造的な悪化が目的関数差を上回る設定だった。
そのため、今回の採択判断では既存軌道同士の OLS 数値を使わず、同一条件の再最適化を行った。

公平比較では次の条件を固定した。

- `duration=10 s`, `fps=60`, `num_harmonics=5`, `base_freq=0.1 Hz`
- base trajectory は全軸 0 から 0 の quintic spline
- 公称範囲は `q=[±0.5 m, ±π rad]`, `dq=[1.5 m/s, π rad/s]`, `ddq=[3.0 m/s², 2π rad/s²]`
- 最適化時は公称範囲へ `0.99` の安全係数を適用
- `use_analytical_bounds=False` とし、`compute_fourier_bounds` は呼ばない
- フーリエ係数は有限 box で制限せず、`q/dq/ddq` を直接制約
- 並進と回転の探索座標は `[0.5, 0.5, 0.5, π, π, π]` で無次元化
- SLSQP、`max_iter=300`、6 restart、seed 42 から 45

比較した目的は次の三つである。

- raw D-opt
- raw 条件数
- 列等化後の条件数

各 family で目的値が最良だった結果は次のとおりである。

| family の目的値最良 | 目的値 | raw cond(F) | 最小特異値 | 列等化 cond(F) | 判定 |
|---|---:|---:|---:|---:|---|
| D-opt seed43 | -115.506 | 6.172 | 101.15 | 2.467 | family 内の目的値最良 |
| raw 条件数 seed42 | 5.510 | 2.347 | 133.65 | 1.396 | 次点 |
| 列等化条件数 seed43 | 1.004 | 208.67 | 1.15 | 1.002 | 不採用 |

列等化条件数 seed43 は回転 3 軸の可動範囲を `0.7%, 1.0%, 0.8%` しか使わなかった。
raw cond(F) と最小特異値も他の二方式より桁で悪かった。
したがって、列等化後の条件数だけを最適化する方式は、現在の並進 3 軸・回転 3 軸の混合系では採用しない。

raw 条件数 seed42 は最小特異値が最も大きく、最悪方向の誤差増幅には強かった。
D-opt 群は raw 条件数群より raw cond(F) と最小特異値で劣った。
一方、D-opt 群は情報行列全体の体積を大きくし、各軸の可動範囲も広く使った。
この比較は実測ノイズ共分散で重み付けした D-opt ではなく、clean regressor に対する raw D-opt である。

D-opt の目的値だけなら seed43 が最良だった。
ただし、評価の主対象は質量、一次モーメント、慣性対角であり、慣性非対角と全体 L2 は副指標である。
この優先順位で D-opt seed44 と raw 条件数 seed42 の単位ノイズ共分散 proxy を比較した。
質量標準偏差は `0.004034` 対 `0.004123` だった。
一次モーメント 3 成分の幾何平均は `0.002106` 対 `0.003255` だった。
慣性対角 3 成分の幾何平均は `0.005639` 対 `0.006938` だった。
D-opt seed44 は、それぞれ約 2%、35%、19% 小さかった。

D-opt seed44 の `raw cond(F)=4.724`、最小特異値は `120.40`、列等化 `cond(F)=2.415` だった。
6 軸の位置可動範囲利用率は `[85.9, 69.6, 89.2, 84.7, 100.0, 100.0]%` だった。
500 Hz 再評価では 0.99 倍した設定制約を最大 0.093% 超えた。
公称制約には 0.908% の余裕が残った。
以上から、方式として D-opt を採用した。
現行の実行用候補は seed44 とした。
raw 条件数 seed42 は、最悪方向を優先する場合の次点として残す。

D-opt の全 24 restart は SLSQP status 8 の `Positive directional derivative for linesearch` で終了した。
軌道は許容した制約誤差内の feasible incumbent だが、ソルバーが局所最適性を宣言した解ではない。
raw 条件数と列等化条件数の選択解は status 0 だった。
このため、D-opt の採択は現行パイプラインを先へ進める判断であり、収束証明ではない。

## Decisions

- 慣性同定用の励起軌道生成には D-opt を採用し、現行成果物は seed44 を使う / 却下: 列等化条件数目的 — エージェント判断
- raw 条件数目的 seed42 を次点として保持する — エージェント判断
